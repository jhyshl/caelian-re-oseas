## 实机证据与结论边界

- 环境：SillyTavern 1.18.0、酒馆助手 4.8.19，地址 `http://127.0.0.1:8000/`。
- 实际选中记录：characterId 为字符串 3，avatar 为 `凯利安beta.png`，主世界书为 `孔雀开屏你说你看不见beta`，可读取 64 条。
- 诊断时拦截并阻止旧调用 `updateCharacterWith('current', card => card)` 的网络写入。读取的是凯利安 beta 内容，但 `/api/characters/edit` 请求目标为 `ch_name: current`、`avatar_url: current.png`。
- 安装目录中的插件源码证实：读取解析了 current 别名，整卡写入使用原始实参。酒馆编辑接口按 avatar_url 保存，目标不存在时可从默认图片生成新文件。这是实际验证的误建路径。
- 旧地区实现先校验助手显示名，并且只接受固定名称的主世界书。实机注入过时名称、空绑定或附加绑定可以复现拒绝。没有声称已复现所有玩家设备上自然发生的初始化时序故障。
- 现有 current.png 早于本次测试存在，修改时间为 2026-09-01 08:07:02 UTC。测试前后 SHA-256 和修改时间一致，角色目录仍为原有 5 个文件，没有新增卡。

## 修改

1. 用 `getContext().characterId` 索引实际角色记录，读取 avatar；必要时按此 avatar 请求 `/api/characters/get`。空 ID 不转换成 0，群聊不冒充单角色。
2. 角色识别支持原有名称，以及实际发行 PNG、文件夹导出和独立脚本中的官方桥接 ID。任意 PNG 文件名、仅名为 beta 的角色均有回归覆盖。不会用显示名称拼接 PNG 文件名。
3. 删除受管更新里的整卡助手写入。描述、作者注释、主/备用开场白用 `/api/characters/merge-attributes`，只传实际 avatar 和待修改字段，然后从同一文件回读。原有脚本精确更新路径继续保留。
4. 优先读取实际角色的主绑定，短暂失败时重新读取持久化卡数据并有限重试。支持唯一可识别的附加世界书；重命名书需要匹配凯利安、特莱奥条目及多个地区标签。多个候选不任意选一本写入。
5. 点击入队、解析目标、异步读取后、更新回调和保存回读后检查角色/主绑定。切换角色时停止该操作，失败不永久缓存。
6. 面板显示真实错误，不再把所有失败都提示为未绑定；支持直接重读，并响应角色/聊天相关事件。

## 实机验收

使用本地固定构建 `worldbook-context-local-fix`，通过酒馆内 `/ejs` 加载并点击实际 UI；没有发送 AI 对话。事先备份角色卡、世界书，测试结束恢复测试替身及临时更新记录。

| 场景 | 结果 |
| --- | --- |
| 助手名称返回 current，助手绑定返回空 | 正确识别实际选中卡和世界书，地区按钮出现 |
| 点击伊拉亚条目关闭、再开启 | 实际保存和回读成功，按钮随状态变化 |
| 地图点击学院节点和正门“前往” | 地点变为 `圣德里安学院 · 正门`，回到酒馆并填入 `前往圣德里安学院的正门` |
| 世界书读取连续抛出临时错误 | 显示具体读取错误，未误报未绑定 |
| 恢复读取后点击“重新读取状态” | 全部地区按钮恢复，无需刷新酒馆 |
| 描述、主开场白、备用开场白原值保存 | 3 个真实 merge-attributes 请求均命中 `凯利安beta.png`，没有 ch_name，没有调用 updateCharacterWith，3 项保存和回读通过 |
| 保存前后卡内 data | 完全一致；此项故意写回原值以保留用户设定 |
| 结束恢复 | 世界书 64 条与初始快照完全一致；地图按保存的初始位置恢复；助手方法全部还原 |

固定构建验收的 `performance.timeOrigin` 始终为 `1788945091652.1`。终检日志 `CAELIAN_FIX_FINAL` 中 `samePage: true`、`sameWorldbook: true`、`helpersRestored: true`。近期成功操作日志没有新增运行时错误。

早期验收工具调用有一次构建导出名错误和一次测试清单格式错误，修正后重新完成对应验收，没有将失败算作通过。
