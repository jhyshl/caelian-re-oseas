# 创意工坊通用积木操作说明

适用：Alpha 84。以下功能位于技能或天赋的「组合规则」编辑器。添加效果时选对应积木；数值或目标旁的公式下拉框可以继续嵌套公式。先保存自己的草稿，再加载示例；加载示例会替换当前组合规则内容。

## 先理解三种对象

- **本次选中目标**：出牌最初选中的单位，进入循环后仍不变。
- **当前目标**：逐个目标执行时，正在处理的单位。
- **当前项**：逐项执行、列表筛选或统计时，正在处理的一份状态、一个单位或一张卡牌。循环嵌套时以最内层为准；要保留外层数据，先用「记录数据」保存。

原生 DOT 每份独立计时。目标有 3 份中毒、2 份灼烧，「读取状态列表 → DOT」会得到 5 项；按「状态种类」去重后得到 2 项。自定义状态的自身数据 `layers` 由作品作者定义，修改它后需要让效果公式读取它，才能影响伤害。

## 每个新增能力如何使用

| 能力 | 操作与例子 |
|---|---|
| 读取状态列表 | 公式选「读取状态列表」，对象选「本次选中目标」，类别选 DOT。种类筛选可选全部，或只勾选中毒、灼烧；指定种类但未勾选任何项会得到空列表。 |
| 状态条件 | 在状态列表里点「添加状态条件」，选「大于」，参数设「读取当前项 → 剩余回合」与 1，只保留剩余超过 1 回合的状态。整场状态读作 -1；需要包含它时，用「或」连接“等于 -1”。 |
| 排除原目标 | 公式选「筛选目标 → 敌方存活单位」，勾选「除选中目标外」。用于循环或效果目标均可。 |
| 逐项执行 | 添加「逐项执行」，遍历列表填上述状态列表。子积木可读取当前项的种类、持有者、原伤害等。遍历单位列表时，当前目标也随之切换。 |
| 筛选列表 | 公式选「筛选列表」，输入列表填敌方目标列表，保留条件填“当前项的生命 < 500”。 |
| 列表排序 | 公式选「列表排序」，输入友方目标列表，每项取值选当前生命，顺序选从小到大。按比例排序时，取值用当前生命 ÷ 生命上限。 |
| 取前 N 项 | 公式选「取前 N 项」，输入上述排序结果，数量填 2。用于选出生命最低的两名队友。 |
| 随机取 N 项 | 输入敌方目标列表，数量填 2，同次抽取不会重复选同一项。数量须为非负整数；超过列表长度时返回全部项。 |
| 数量 | 公式选「数量」，只保留一个参数，填状态列表。3 份中毒、2 份灼烧得到 5。 |
| 列表去重 | 输入状态列表，字段选状态种类。上例得到中毒、灼烧各一项，保留各类首次出现的条目。 |
| 列表求和 | 输入 DOT 列表，每项取值选每跳原伤害。30、30、30、50、50 得到 190。 |
| 列表最小／最大值 | 输入同一列表，每项取值选每跳原伤害，分别得到 30、50。空列表的求和、最小值和最大值都为 0。 |
| 读取卡牌列表 | 选择手牌、抽牌堆、弃牌堆或移出牌；可按费用、星级、卡牌编号筛选和统计。例如列表求和的每项取值选卡牌费用，得到所选牌堆当前费用总和。 |
| 修改状态 | 状态列表选指定 DOT；字段选剩余回合，方式选增加，数值填 2，将所选实例各延长 2 回合。也可设定或按倍率修改状态数值、DOT 原伤害、自定义数据。 |
| 修改份数 | 先用「取前 N 项 → 1」选一份 DOT，再将层数／份数设置为 3，得到该份的三个副本。不要把三份都选中后各设为 3，否则会分别处理它们。已有上限仍生效。 |
| 合并持续时间 | 自定义状态叠加方式选「合并额度」，再选保持原到期时间、刷新为本次持续回合或延长本次持续回合。例：剩余 2 回合时再施加 3 回合，分别变成 2、3、5 回合。 |
| 复制／转移状态 | 选择状态列表和接收目标。复制保留原状态；转移在成功放到接收目标后移除原状态。可保留原施加者和伤害，也可改由当前持有者施加；默认保留剩余回合，勾选重设持续回合后可填写新时间。 |
| 按列表移除 | 添加「移除状态」，勾选「从状态列表选择实例」，填读取或提前记录的列表。只移除列表指向的实例，包括不可净化状态。移除自定义父状态时附带效果也移除。 |
| 按持续伤害结算 | 「造成伤害 → 伤害处理 → 按持续伤害结算」。数值填基础伤害，可读取当前 DOT 的每跳原伤害；还可以指定原施加者及等级。会计算目标防御与护盾，不再额外乘星级，不暴击、不闪避。 |
| 读取完整事件 | 公式选「读取事件」，按触发事件选择实际扣除生命、护盾吸收、是否暴击、是否持续伤害、是否追加／反应伤害、来源卡牌编号或实例等字段。只有对应事件实际携带的字段有意义；例如治疗事件读溢出治疗，伤害后事件读实际扣血。 |
| 跨卡牌共享数据 | 数据范围选「同队共享（跨卡牌）」。A 卡增减“热量”+1，B 卡读取同范围的“热量”×30 作为伤害。同队使用相同名称会共享；不同队伍隔离。 |
| 本回合共享数据 | 使用「同队本回合共享」，每回合重新取声明初始值，适合连击数。与旧的“本回合”范围不同，它可以跨组合规则共享。 |
| 按目标记录 | 使用「按目标记录（跨卡牌）」或「按目标本回合记录」。例如对每名敌人分别累计“命中次数”；换目标时读取各自记录，回合版在下回合重新开始。 |
| 数据选择器 | 「读取记录」会列出相同范围内声明的数据和已保存的执行结果；「读取当前项」会列出中文字段与已定义的状态自身数据。其他作品共享的数据仍可手填相同名称。 |
| 执行记录 | 战斗中打开「积木执行记录」，查看执行效果、筛选结果、条件不成立、冷却或本回合已触发等说明。保留最近 150 条记录，也可在工坊测试战斗中查看。 |

## 单位和时间不要混淆

- 「使用已有状态效果」中的 DOT 数值是**攻击倍率**：0.35 表示攻击力的 35%，不是固定 0.35 点伤害。星级和施加时攻击会影响快照；每跳再计算目标防御、护盾。
- 「修改状态 → DOT 每跳原伤害」以及「造成伤害 → 按持续伤害结算」填的是**伤害数值**：35 就是 35 点减伤前基础伤害。
- 普通施加或复制时，持续回合填正整数，-1 表示整场。修改剩余回合时，0 表示移除，-1 表示整场；给整场状态增加回合不会缩短它。
- 原生 DOT 的层数／份数指独立实例数量。自定义状态的 `layers` 是数据字段；可以让复用 DOT 的倍率公式等于 `layers × 0.2`，实现同一个状态内的伤害叠加。
- 读取“全部状态／Buff／Debuff”时，自定义复合状态以父状态出现；读取 DOT 时会列出实际附带的每份 DOT，适合逐份伤害处理。只移除附带 DOT 不等于移除父状态；若父状态机制会持续复用该效果，应选择父状态一并移除。

## 组合一：只把原目标已有的 DOT 种类施加给其他敌人

可直接加载「积木组合：按种类扩散状态」。手工制作如下：

1. 触发事件选施放时，添加「逐项执行」。
2. 遍历列表选「列表去重」，去重字段选「状态种类」。输入列表选「读取状态列表 → 本次选中目标 → DOT」。
3. 如只处理中毒和灼烧，在这个读取列表中启用指定种类，只勾选这两项。还可附加剩余回合、来源等条件。
4. 在循环内部添加「使用已有状态效果」，勾选「按公式选择效果种类」，效果种类选「读取当前项 → 状态种类」。
5. 目标选「筛选目标 → 敌方存活单位」，勾选「除选中目标外」。
6. 数值填 0.35、持续回合填 2、可叠加上限填 3、基础命中率填 100。这是为其他敌人重新施加的新 DOT，按当前施加者攻击计算，并按效果命中规则判定。

原目标只有中毒，就只尝试施加中毒；原目标同时有中毒和灼烧，就各施加一种。原目标不受影响。如果想保留原倍率、剩余回合和施加者，则把第 4 步换成「复制／转移状态 → 复制」，状态列表填「读取当前项 → 当前项整体」。

## 组合二：按 3 份中毒与 2 份灼烧的原伤害结算，再移除

可直接加载「积木组合：读取原伤害并移除状态」。手工制作如下：

1. 添加「记录数据」，范围选本次执行，名称填“待处理状态”，值填「读取状态列表 → 本次选中目标 → DOT」。在这里设置种类与条件筛选。
2. 添加「逐项执行」，遍历列表填「读取记录 → 本次执行 → 待处理状态」。
3. 循环内部添加「造成伤害」，处理方式选「按持续伤害结算」。数值填「读取当前项 → 每跳原伤害」，目标填「读取当前项 → 状态持有者编号」。
4. 伤害来源填「读取当前项 → 原施加者编号」，勾选指定来源等级，填「读取当前项 → 原施加者等级」。
5. 循环结束后添加「移除状态」，勾选按列表选择实例，填同一份“待处理状态”记录。

3 份每跳 30 的中毒、2 份每跳 50 的灼烧，总基础伤害为 190。每份分别按原等级计算目标防御，再扣护盾与生命，因此实际扣血可能低于 190。该组合结算每份的一跳；要结算剩余所有跳数，可把第 3 步数值改为“每跳原伤害 × 剩余回合”，并单独决定整场状态如何计算，不能直接乘 -1。

先记录再移除，可以保证伤害事件期间后来新施加的状态不被误删。若作者需要删除结算后目标当时的全部 DOT，可在最后重新读取 DOT 列表作为移除对象。

## 组合三：随机选出两名满足条件的敌人

添加「逐个目标执行」，目标填「随机取 N 项」，数量 2。输入列表填「筛选列表」，原列表用「筛选目标 → 敌方存活单位」，保留条件用“读取当前项的当前生命 < 500”。在循环内对「当前目标」施加状态或伤害。

换成「列表排序 → 从小到大 → 当前生命」，外层用「取前 N 项」，就能稳定选择生命最低的两名单位。内置示例「积木组合：治疗生命最低的两名队友」展示了这一组合。

## 进阶：跨卡牌协作、按目标限制、选择最强两份状态转移

目标机制：A 卡积累团队热量。B 卡花费 3 热量，把原目标身上伤害最高的两份中毒／灼烧转移给随机一名其他敌人，并把其每跳原伤害提高 50%；每名原目标每回合最多执行一次。

### A 卡

1. 组合数据声明“热量”，范围同队共享，初始值 0。
2. 施放时添加「增减数据 → 同队共享 → 热量 → 1」。

### B 卡

1. 同样声明“热量”（同队共享，初始 0），并声明“已处理”（按目标本回合记录，初始 0）。
2. 规则条件设“热量 ≥ 3 且 已处理 = 0”。
3. 记录“候选状态”：读取原目标 DOT，种类勾选中毒、灼烧，再用列表排序按每跳原伤害从大到小，外层取前 2 项。
4. 记录“接收者”：筛选敌方存活单位并排除选中目标，再随机取 1 项。
5. 添加「如果／否则」，条件设“候选状态数量 > 0 且 接收者数量 > 0”。后续步骤放在成立分支中。
6. 增减同队共享热量 -3；记录按目标本回合“已处理”为 1。
7. 添加「修改状态」，状态列表读取“候选状态”，字段每跳原伤害，方式乘以倍率，数值 1.5。
8. 添加「复制／转移状态」，状态列表读取“候选状态”，目标读取“接收者”，操作转移，保留原施加者与原伤害，不重设持续回合。

这样，筛选、排序、记录、资源消耗、状态修改与转移都能独立替换。上述设计在满足候选与接收条件后先扣热量；若接收目标已有更强状态且上限已满，转移仍可能失败，原状态保留且热量已消费。需要其他资源返还规则时，可把复制／转移的执行结果保存，再根据成功数量编排后续分支。

## 保存与验证

完成后点击结构检查，保存草稿，再保存职业。建议在工坊测试战斗中配置多名木桩，通过执行记录核对：读取数量、原目标排除、选中状态是否正确、回合是否保留、跨卡牌数据是否共享。先用简单数值和固定目标检查，再加入随机、事件联动及复杂公式。
